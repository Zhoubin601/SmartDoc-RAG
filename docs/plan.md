## 阶段五：提交前优化（建议优先完成）

### P0：优先处理——影响功能可靠性或文档准确性

- [ ] **修复本地向量模型的持久化恢复问题。**
  - 现状：`SmartVectorStore.save_local()` 保存了文档和向量矩阵，但 `LocalTfidfEmbeddings` 的已拟合词表、IDF 等状态没有一起保存；目前应用启动流程也没有自动加载已有向量库。
  - 任务：将 TF-IDF 向量器状态与文档、向量矩阵一起持久化并在恢复时加载；同时校验向量维度与文档数量。若短期内不实现自动恢复，应在 README 中明确说明重启后需要重新构建知识库。
  - 验收：构建知识库后重启应用，恢复索引并查询同一个问题，检索结果维度正确且结果合理；不能只验证文件存在。

- [ ] **明确多轮对话的实际行为。**
  - 现状：`app.py` 会保存和展示聊天历史，但 `rag_engine.py` 当前只将本轮问题和检索到的片段传给提示词，没有把历史消息传入模型。
  - 任务（二选一）：优先实现有限轮数的历史上下文注入，并明确区分历史对话与检索资料；若不打算实现，则修改 README，说明每轮回答独立生成，避免宣称支持有上下文记忆的多轮问答。
  - 验收：先问一个问题，再用“刚才提到的内容”等指代继续追问，检查回答是否能正确关联上一轮；若选择不实现，则文档表述与行为一致。

- [ ] **校准 README 与代码实现的一致性。**
  - 现状：README 提到 `RunnablePassthrough`，但当前 `rag_engine.py` 的实际链路是 `ChatPromptTemplate | LLM | StrOutputParser`；本地默认向量方案是 TF-IDF 字符 n-gram 检索，并非深度语义嵌入模型。
  - 任务：按实际实现修改说明，或在确有必要时补齐相应代码；把“高精度语义检索”“杜绝幻觉”等绝对化说法改成审慎、可验证的描述。
  - 验收：README 的组件、检索原理、功能边界与源码一致；不把相似度分数描述成回答正确率或可靠性保证。

- [ ] **改善文档解析失败时的反馈。**
  - 现状：`load_and_split_files()` 捕获异常后主要通过终端打印，界面不一定能清楚告诉用户具体哪个文件失败。
  - 任务：收集解析成功与失败的文件清单，在 Streamlit 页面显示失败原因；对无法提取文本的 PDF 给出明确提示。
  - 验收：上传一个正常文档和一个无法解析的文件时，应用能够说明成功、失败数量及失败文件。

### P1：建议完善——提升使用体验和项目质量

- [ ] **处理上传文件名冲突与输入边界。**
  - 任务：避免同名文件互相覆盖；对文件大小、空文件、支持的扩展名和异常输入做基本校验。
  - 验收：上传两个同名文件时不会静默覆盖；错误输入会得到可理解的提示。

- [ ] **改进检索结果的相关性判断。**
  - 任务：评估低相似度结果，必要时设置可配置的最低相关性阈值；没有可靠参考片段时提示用户资料不足，而不是把低相关片段当成可靠依据。
  - 注意：TF-IDF 相似度不是模型置信度，阈值需要通过样例测试确定，不要直接使用未经验证的固定值。
  - 验收：用文档内可回答问题和文档外问题分别测试，记录误召回与漏召回情况。

- [ ] **补齐依赖与基础自动化测试。**
  - 任务：检查 `Code/requirements.txt` 是否显式列出直接导入的依赖（例如 `langchain-text-splitters`）；增加文档解析、向量检索、持久化恢复和无相关资料等测试。
  - 验收：在干净的 Python 3.10+ 环境按 README 安装依赖后可启动；核心测试可以重复运行。

- [ ] **整理演示与验收材料。**
  - 任务：准备一份不含隐私和密钥的演示文档，记录启动命令、测试问题、回答及引用来源；可在 README 加入实际运行截图。
  - 验收：其他人按照文档可以复现最基本的上传、检索和问答流程。
